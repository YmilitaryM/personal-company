## 部门定义

### 1. AI/ML 部门 (11人)
**负责**: 机器学习算法、智能体知识库、RAG系统
- PM-A: 产品方向
- TL-A: 技术交付
- ML专业组长: 算法方向技术深度
- Agent专业组长: 知识库/智能体方向
- 高级工程师 ×4: 核心开发
- ML专业工程师 ×2: 模型训练、特征工程
- Agent专业工程师 ×2: 知识库构建、智能体开发

### 2. IoT 部门 (9人)
**负责**: IoT场景应用、边缘计算、设备管理
- PM-B: 产品方向
- TL-B: 技术交付
- 嵌入式专业组长: 固件/协议方向
- 高级工程师 ×4: 核心开发
- IoT专业工程师 ×2: 嵌入式、协议、硬件对接

### 3. App & Web 部门 (7人)
**负责**: 移动应用、Web应用、用户端产品
- PM-C: 产品方向
- TL-C: 技术交付
- 前端专业组长: 前端架构方向
- 高级工程师 ×4: 核心开发
- 专业工程师 ×2: 移动端、性能优化

### 4. 横切团队

#### 设计部 (4人) — 虚线汇报给 CTO
- UI设计组长: 设计系统、组件库
- UI设计师 ×1: 视觉设计
- UX设计组长: 交互规范、用户研究
- UX设计师 ×1: 可用性测试、原型

#### DevOps/SRE (2人) — 实线汇报给 CTO
- DevOps工程师 ×2: CI/CD、基础设施、监控、安全

#### 市场部 (1人)
- 市场经理: 市场调研、竞品、GTM

#### 独立评审团 (3人) — 独立于所有部门
- 不隶属于任何部门，直接向CTO报告评审结果

## 专业组长职责

专业组长是项目的技术纵深保障，在项目组长(TL)领导下工作：

| 角色 | 归属项目 | 职责 |
|------|----------|------|
| ML专业组长 | AI/ML项目 | 算法选型评审、模型架构设计、训练方案审核 |
| Agent专业组长 | AI/ML项目 | 知识图谱设计、RAG策略、Prompt工程规范 |
| 嵌入式专业组长 | IoT项目 | 固件架构、通信协议选型、硬件兼容评审 |
| 前端专业组长 | App&Web项目 | 前端架构、设计系统实现、性能基准 |

**专业组长 vs 项目组长**:
- 项目组长(TL): 管人、管进度、管交付
- 专业组长: 管技术深度、管领域质量、管技术规范

## DevOps/SRE 职责

### DevOps 工程师 (2人)
- CI/CD 流水线设计与维护
- 基础设施即代码 (IaC)
- 容器化与编排 (Docker/K8s)
- 监控与告警系统
- 安全合规扫描
- 发布管理与回滚
- 成本优化

**工作方式**: DevOps 不作为独立项目组，而是嵌入到各项目的开发流程中：
- 项目创建 → DevOps 初始化 CI/CD 配置
- 开发阶段 → DevOps 维护流水线、处理构建问题
- 评审阶段 → DevOps 提供质量指标数据
- 交付阶段 → DevOps 负责部署和回滚方案

## 资源分配追踪

### 人员状态定义
| 状态 | 含义 | Dashboard 显示 |
|------|------|---------------|
| Active | 已分配项目，有活跃任务 | 🟢 |
| Standby | 已分配项目，等待任务 | 🟡 |
| Idle | 未分配项目，空闲 | ⚪ |
| Overload | 任务过多，需要重新分配 | 🔴 |
| Leave | 休假/不可用 | ⚫ |

### 负载计算
```
负载率 = (已分配任务预估工时 / 可用工作时间) × 100%
  < 60%: 空闲，可接新任务
  60-85%: 正常负载
  85-100%: 高负载，需要关注
  >100%: 超负荷，需要立即调整
```

## 职业梯度 (内部)

```
L1: 初级工程师 → 执行明确任务，需要指导
L2: 专业工程师 → 独立完成领域任务
L3: 高级工程师 → 设计模块方案，Review他人代码
L4: 专业组长   → 领域技术权威，制定规范
L5: 项目组长   → 管理项目交付，团队管理
L6: CTO/总监   → 技术战略，跨项目决策
```

晋升条件:
- L1→L2: 连续2个项目独立完成，无P0/P1 Bug
- L2→L3: 主导一个完整功能模块的设计和交付
- L3→L4: 制定一项领域技术规范并推广到全部门
- L4→L5: 完整交付一个项目，所有阶段评审通过
- L5→L6: 战略贡献，跨部门影响力

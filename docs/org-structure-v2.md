# 公司组织架构 V2

## 总览

- **模式**: AI Agent 团队自运转
- **运作方式**: 需求方 → AI团队自运转 → 交付验收
- **产品范围**: ML算法、IoT场景、Agent知识库、App & Web

## 部门定义

### 1. AI/ML 部门
**负责**: 机器学习算法、智能体知识库、RAG系统
- PM-A: 产品方向
- TL-A: 技术交付
- ML专业组长: 算法方向技术深度
- Agent专业组长: 知识库/智能体方向
- 高级工程师: 核心开发
- ML专业工程师: 模型训练、特征工程
- Agent专业工程师: 知识库构建、智能体开发

### 2. IoT 部门
**负责**: IoT场景应用、边缘计算、设备管理
- PM-B: 产品方向
- TL-B: 技术交付
- 嵌入式专业组长: 固件/协议方向
- 高级工程师: 核心开发
- IoT专业工程师: 嵌入式、协议、硬件对接

### 3. App & Web 部门
**负责**: 移动应用、Web应用、用户端产品
- PM-C: 产品方向
- TL-C: 技术交付
- 前端专业组长: 前端架构方向
- 高级工程师: 核心开发
- 专业工程师: 移动端、性能优化

### 4. 横切团队

#### 设计部 — 虚线汇报给 CTO
- UI/UX 设计师: 设计系统、组件库、交互规范、用户研究

#### DevOps/SRE — 实线汇报给 CTO
- DevOps 工程师: CI/CD、基础设施、监控、安全

#### 市场部
- 市场经理: 市场调研、竞品、GTM

#### 独立评审团 — 独立于所有部门
- R1 (架构专家), R2 (产品质量), R3 (工程效率)
- 不隶属于任何部门，直接向CTO报告评审结果

## 专业组长职责

专业组长是项目的技术纵深保障，在项目组长(TL)领导下工作：

| 角色 | 归属项目 | 职责 |
|------|----------|------|
| ML专业组长 | AI/ML项目 | 算法选型评审、模型架构设计、训练方案审核 |
| Agent专业组长 | AI/ML项目 | 知识图谱设计、RAG策略、Prompt工程规范 |
| 嵌入式专业组长 | IoT项目 | 固件架构、通信协议选型、硬件兼容评审 |
| 前端专业组长 | App&Web项目 | 前端架构、设计系统实现、性能基准 |

**专业组长 vs 项目组长**:
- 项目组长(TL): 管人、管进度、管交付
- 专业组长: 管技术深度、管领域质量、管技术规范

## DevOps/SRE 职责

### DevOps 工程师
- CI/CD 流水线设计与维护
- 基础设施即代码 (IaC)
- 容器化与编排 (Docker/K8s)
- 监控与告警系统
- 安全合规扫描
- 发布管理与回滚
- 成本优化

**工作方式**: DevOps 不作为独立项目组，而是嵌入到各项目的开发流程中：
- 项目创建 → DevOps 初始化 CI/CD 配置
- 开发阶段 → DevOps 维护流水线、处理构建问题
- 评审阶段 → DevOps 提供质量指标数据
- 交付阶段 → DevOps 负责部署和回滚方案

## 人员状态定义

| 状态 | 含义 |
|------|------|
| Active | 已分配项目，有活跃任务 |
| Standby | 已分配项目，等待任务 |
| Idle | 未分配项目，空闲 |
| Overload | 任务过多，需要重新分配 |
| Leave | 休假/不可用 |
